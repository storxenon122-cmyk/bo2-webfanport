## Architecture gotchas (learned the hard way — don't regress)
- **`cyl()` / `box()` only BUILD a mesh — they never parent it.** A bare `cyl(...)` leaves an orphan that silently disappears (that was the "detached scope/barrel" bug on all 18 guns). Use `cylIn(grp, ...)` when the part belongs inside a group, and check `grp.add(...)` for boxes too.
- **`applyGunEnv(renderer)` (called once from `main.js boot()`)** builds the procedural PMREM probe and assigns it **only** to `GUN_ENV_METALS` materials. Never assign `scene.environment` instead — with a bright probe it greys out the whole world, and gun metals with metalness≈1 and no probe render pure black.
- **`HUD._lc` is a last-written-value cache**; `HUD._slot` caches the streak-slot sub-elements. The per-frame setters (`setScore`/`setStreaks`/`setCrosshair`/`setScope`/`setSprintVignette`/`setHealth`) early-return when nothing changed. If you add a per-frame DOM write, guard it the same way or you reintroduce constant layout invalidation. **Always invalidate the relevant `_lc` key** if you mutate the DOM behind its back.
- **`Killstreaks.progress()` returns `pct:1` while a streak is deployed** (cam up / UAV timer) — use it for the *highlight* only, never for the fill bar, or a bar will show 100 % next to a `0/950` label. The fill must always be `min(raw,cost)/cost`.
- **`MapRotation.set(id)` selects the map, not `Settings.data.map`** — `Game.start()` reads `MapRotation.current`. Test scripts that set `Settings.data.map` will silently rebuild Cargo 17 every time.
- **`scene.add(camera)` is mandatory** (`main.js`) — viewmodel is a camera child; without it the gun never renders.
- **`resolveCollision(center, half, colliders, stepHeight, moveDir)`** — first arg is the AABB **center** (not feet); `moveDir` must include `y` (both call sites pass `{x,y,z}` of current velocity) or step-up will trigger mid-jump. Step-up requires headroom (checks other colliders at the lifted position) — with stairwell-holed slabs this never blocks; with solid slabs above stairs the climber gets stuck, which is how you know a hole is missing. Stair step rise ≤ 0.48 (player step 0.5, bot step 0.55); roof parapets sit 0.6 above roof top so they block step-up.
- **`Input.pressed(action)` consumes the edge on first read** — never read the same action twice in one frame (this exact bug silently killed normal jumping: a dolphin-dive check read `pressed('jump')` first, the real jump check never saw it). Read once into a local const and share it. **Jump also requires `p.grounded`** — if you teleport the player in a test, wait for a landing before pressing Space or the edge is consumed while airborne and the jump "fails".
- **Digit keys are dual-use**: `Settings.binds` maps Digit1 to BOTH `weapon1` and `streak1`; `Input.rebind()` last-write-wins so edges only fire `streak1`. `game.js` handles digit logic centrally (streak if ready, else weapon swap). If adding binds, keep this centralized.
- **Init guards exist**: `Effects.init` and `Viewmodel.init` early-return on 2nd game start — keep them.
- **`Game.die()` timer**: guarded with `if (this.state==='dead')` — stale timers caused a phantom K.I.A. screen once.
- Pause flow: pointer-lock loss → `Game.pause()` (`main.js` onLockChange); `Escape` handled via `Input._onPause`.
